Overview

I designed and taped out a sequential 8-bit SAR ADC with a differential input. The signal path starts with a transmission-gate input sampler feeding a capacitive DAC (CDAC); the switches on the CDAC are controlled by a custom SAR logic block that resolves one bit per clock cycle.

The SAR logic itself is a chain of D flip-flops — one per bit — where each DFF turns on the next bit's decision cycle in sequence. When a bit becomes active, it drives a small pipeline: the SAR data registry captures that bit's decision, which enables the active registry, which enables the switch driver, which physically sets that bit's CDAC switches. Once a bit resolves, the chain hands off to the next bit, and a final "done" signal flags when all 8 bits have been decided.

Every gate in this design — NAND, NOR, inverters, the DFFs, the muxes — was built and laid out by hand rather than pulled from a standard cell library, which put the full instance count over 1,300. The SAR logic layout in particular is something I'm proud of: it's dense, and getting the timing and routing to work cleanly in that footprint took a lot of iteration.

Each CDAC switch is referenced to the common-mode voltage (0.9V) during sampling. Once a bit's decision is made, the corresponding DFF output connects that bit's capacitor to either VDD (1.8V) or VSS (0V), depending on two things: the comparator's output for that cycle, and whether the capacitor sits in the positive or negative cap chain. That combination is what steers each bit toward the correct code during the successive approximation.

System Architecture

The top level ties together eight parallel bit-slices, each with its own SAR data registry, active registry, and switch driver, sharing a common clock and sample/convert control path.

Input Sampling & CDAC Switches

Transmission-gate switches sample the differential input onto the capacitor array, with dedicated switches for the common-mode and reference voltages used during bit resolution.

SAR Logic — DFF Chain

The SAR logic is built from a chain of custom D flip-flops. Each DFF controls when its corresponding bit becomes "active" and hands off to the next bit once a decision is captured — this is what sequences the whole conversion, one bit per clock cycle.

Switch Driver Logic

Once a bit's active registry fires, the switch driver logic — built from NAND gates and inverters — generates the control signals that physically set that bit's CDAC switches.

Design Challenges

The top-level pad frame connection gave me the most trouble. Late in the process I ran into DRC errors on the top metal layer that I wasn't able to fully resolve — I tried adding diodes and series resistors, but the errors persisted. Given the timeline, I ended up finishing that portion of the layout in a rushed state rather than the clean version I'd wanted, which shows up as some extra power consumption in the final design. It's the one part of the chip I'd go back and redo with more time.

ENOB also dropped from 7.3 bits pre-layout to 7.1 bits post-layout at a 10MHz clock. My best guess is transistor sizing in a few key devices — likely undersized somewhere in the comparator or switch path — introducing enough mismatch or settling error to cost that extra 0.2 bits. If I revisit this design, resizing those transistors and re-running the sizing analysis is the first thing I'd check.
